Agent inbox collects what needs you next across your agent sessions: decisions only you can make, results to look at, permission requests, and dispatched work that came back. Each card holds one of them, grouped under the session that filed it, with sessions it started nested underneath and sessions grouped by workspace; workspaces and sessions fold. Every agent card opens with three steps that remind you where it came from (what you asked, what the session did, what now waits for you). You can pick an answer right on the card and send it into the session, answer a permission request, or mark a result or returned work as seen.

Agents file cards themselves through three tools served to every interactive session by a plugin-owned MCP server: `queue_add`, `queue_track` and `queue_resolve`. The session a card belongs to comes from the launch configuration, not from the agent. Permission requests, failed turns and tracked `paseo run` children that finish are recorded without agent involvement.

Cards live in a local SQLite file, `~/.local/share/agent-queue/queue.db` by default (`AGENT_QUEUE_DB` in the daemon's environment moves it), shared with the `agent-queue` command line tool, through which agents on other hosts can file cards too. Answers sent into a session are in English; `AGENT_INBOX_LANG=zh` switches them to Chinese. The daemon needs Node 25 for `node:sqlite`.
